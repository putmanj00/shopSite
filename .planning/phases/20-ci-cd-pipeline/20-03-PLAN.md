  <name>Task 1: Push CI workflow and trigger first CI run</name>
  <files>.github/workflows/ci.yml</files>
  <action>
The CI workflow (Plan 02) must be pushed to a branch and a PR opened against main to trigger the first workflow run. Without a first run, the check names do not appear in GitHub's branch protection UI, making it impossible to configure required checks.

Step 1 — Confirm the workflow file exists and is committed:
```bash
git status .github/workflows/ci.yml
git log --oneline -3
```

Step 2 — Verify GitHub Secrets are configured. Run:
```bash
gh secret list
```
The following secrets must be present before the quality and e2e jobs can pass:
- SHOPIFY_STORE_DOMAIN
- SHOPIFY_STOREFRONT_ACCESS_TOKEN
- SHOPIFY_SHOP_ID

If any are missing, create them:
```bash
gh secret set SHOPIFY_STORE_DOMAIN
gh secret set SHOPIFY_STOREFRONT_ACCESS_TOKEN
gh secret set SHOPIFY_SHOP_ID
```
(The CLI will prompt for the value securely without exposing it in shell history.)

Step 3 — If the workflow changes are not yet on a PR branch, create one:
```bash
git checkout -b feat/20-ci-pipeline
git push -u origin feat/20-ci-pipeline
gh pr create --title "feat(20): CI/CD pipeline" --body "Adds GitHub Actions CI workflow with lint, typecheck, build, E2E (3 browsers), secrets scan, and npm audit. Closes CICD-01–05, CICD-07, DEVX-03."
```

Step 4 — Confirm the workflow run started:
```bash
gh run list --limit 5
```
Wait for the run to complete (or reach a point where check names are visible in the GitHub UI). Monitor progress:
```bash
gh run watch
```

Note: The first run may fail if GitHub Secrets are not yet configured for Shopify. That is acceptable for this task — the goal is for the check NAMES to appear in GitHub, not for all checks to pass immediately.
